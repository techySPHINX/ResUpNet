# ResUpNet Audit

Date: 2026-06-19

## Local Status

The active project is a Phase 2 PyTorch pipeline for binary whole-tumor
segmentation on Kaggle BraTS 2021 Task 1.

- Active split: `experiments/v2_multimodal_roi/processed_splits`
- Shape: `160x160x4`
- Channels: `T1`, `T1ce`, `T2`, `FLAIR`
- Patients: train `875`, validation `188`, test `188`
- Patient overlap: none
- Backend: native Windows PyTorch CUDA on RTX 5050 Laptop GPU

The prepared dataset exists and has valid patient-wise split metadata. The
current validation and test arrays are not full BraTS volumes; they are selected
slices generated by the project slice policy.

## What Can Be Claimed Now

The checked-in training artifacts are internally consistent and support the
reported selected-slice validation metrics above.

The current differentiators are:

- four-modality MRI input instead of single-channel input
- patient-wise split with no overlap
- image-intensity ROI cropping, not mask-localized cropping
- tumor, near-tumor, and hard-negative slice selection
- residual U-Net style encoder-decoder
- attention-gated skip connections
- ASPP bottleneck for multi-scale context
- combined Dice, focal Tversky, boundary, and BCE loss
- validation-only threshold selection
- optional TTA and connected-component post-processing during evaluation
- conservative MRI augmentation, gradient clipping, EMA checkpointing, and
  full optimizer/scheduler/scaler resume support before the full run
- patient/slice metadata and global confusion-derived metrics in evaluation

## What Cannot Be Claimed Yet

Do not claim that no one has trained on BraTS 2021. BraTS 2021 is a public
benchmark and published methods have already trained and evaluated on it,
including whole-tumor Dice around 90%.

Do not claim official BraTS full-volume superiority from these artifacts alone.
The result is validated for the current selected-slice validation protocol, not
for an official challenge-style full-volume test protocol.

For publication-grade reproducibility, the selected-slice artifact result should
still be connected to:

1. a completed training run,
2. the saved `best_model.pt`,
3. the matching `logs/history.json`,
4. validation-threshold test evaluation,
5. `evaluation_summary.json`,
6. per-sample or per-patient metric files.

Do not compare selected-slice Dice directly with official BraTS full-volume
Dice as a leaderboard claim. For benchmark-quality reporting, add full-volume
or patient-level evaluation.

## Minimum Credible Result Path

Run the full native training command:

```powershell
python -B train_phase2_resupnet_torch.py --data-dir experiments\v2_multimodal_roi\processed_splits --epochs 150 --batch-size 8 --base-filters 32 --mixed-precision --output-dir E:\ResUpNet\runs\resupnet_torch_cuda_8gb
```

Then run evaluation from the best checkpoint:

```powershell
python -B evaluate_phase2_model_torch.py --data-dir experiments\v2_multimodal_roi\processed_splits --model-path E:\ResUpNet\runs\resupnet_torch_cuda_8gb\checkpoints\best_model.pt --output-dir E:\ResUpNet\runs\resupnet_torch_cuda_8gb\evaluation_tta_post --tta --postprocess --min-component-size 32
```

If the EMA checkpoint exists and validates better, evaluate it separately:

```powershell
python -B evaluate_phase2_model_torch.py --data-dir experiments\v2_multimodal_roi\processed_splits --model-path E:\ResUpNet\runs\resupnet_torch_cuda_8gb\checkpoints\best_ema_model.pt --output-dir E:\ResUpNet\runs\resupnet_torch_cuda_8gb\evaluation_ema_tta_post --tta --postprocess --min-component-size 32
```

Report these together:

- tumor-row Dice, IoU, precision, recall, F1
- global confusion-derived Dice, IoU, precision, recall, F1
- all-row Dice and IoU
- HD95 and ASD
- empty-true false positives
- selected validation threshold

- train/validation split details
